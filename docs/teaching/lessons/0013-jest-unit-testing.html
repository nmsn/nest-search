1. 为什么 NestJS 项目必须有测试

你 principles 轨道(0009-0012)刚写完 ~12 节 ~2500 行新代码 + 4 次 commit。没有测试保护,改任何一行都可能 break 另一个角落。

具体场景:

  • 0010 改了 ProxyService 的 axios 用法 → 0011 改 RolesGuard 时,谁保证 ProxyService 还工作?
  • 0011 改了 RolesGuard 的 metadata key → 0009 写的 @Roles 装饰器还能匹配吗?
  • 0012 把 AppController 拆出去 → 那些 proxy 路由还能正常转发吗?

没有测试,只能"每改一处手动 curl 一遍" — 慢、漏、不持续。

有测试,改一处 1 秒内知道有没有破坏其他地方。

2. Jest 基础 — describe / it / expect

Jest 是 Node 生态最常用的测试框架。你项目已经装了 jest 30.4.1 + ts-jest 29.4.9(NestJS 测试标配)。

3 个核心概念

describe('RolesGuard', () => {           // ← 一组相关测试(套件)
  it('allows when no @Roles metadata', () => {       // ← 一个具体测试(用例)
    expect(guard.canActivate(ctx)).toBe(true);     // ← 断言
  });

  it('denies when user lacks role', () => {
    expect(guard.canActivate(ctx)).toBe(false);
  });
});

AAA pattern(准备 / 执行 / 断言)

it('xxxxx', () => {
  // Arrange — 准备数据
  const ctx = makeMockContext('admin');

  // Act — 执行
  const result = guard.canActivate(ctx);

  // Assert — 断言
  expect(result).toBe(true);
});

三段分清楚 = 测试可读、好维护、好复用。

3. Mocking — jest.fn() / jest.spyOn()

单元测试的核心是隔离被测代码。RolesGuard 依赖 Reflector,ProxyService 依赖 HttpClientService — 测试时这些依赖要被 mock。

jest.fn() — 创建 mock 函数

const mockFn = jest.fn();              // ← 一个空 mock
mockFn.mockReturnValue(42);          // ← 调它返 42
mockFn.mockResolvedValue({ ok: true }); // ← 调它(异步)返 { ok: true }
mockFn.mockImplementation((x) => x * 2);  // ← 自定义逻辑

expect(mockFn).toHaveBeenCalled();    // ← 断言"被调过"
expect(mockFn).toHaveBeenCalledWith('admin', 'editor');  // ← 断言"用这些参数调过"

jest.spyOn() — spy 现有方法

const spy = jest.spyOn(reflector, 'getAllAndOverride');
spy.mockReturnValue(['admin']);  // ← 替换方法行为

// 测试结束后恢复
spy.mockRestore();

区别:jest.fn() 是创建新 mock;jest.spyOn() 是 spy 已有对象的方法。

4.0 · 准备:加 jest 配置 + test script

先建基础设施 — 3 个文件:

新建 jest.config.js(项目根):

module.exports = {
  preset: 'ts-jest',
  testEnvironment: 'node',
  rootDir: '.',
  roots: ['<rootDir>/apps/'],           // ← 只测 apps/ 下的代码(忽略前端)
  testMatch: ['**/*.spec.ts'],         // ← .spec.ts 后缀的文件
  moduleFileExtensions: ['ts', 'js', 'json'],
  transform: {
    '^.+\\.(t|j)s$': ['ts-jest', { tsconfig: 'tsconfig.spec.json' }],
  },
};

新建 tsconfig.spec.json(项目根,专门给测试用):

{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "types": ["jest", "node"],   // ← 必须显式声明,否则 .spec.ts 里 describe/it/expect 全找不到
    "esModuleInterop": true,
    "emitDecoratorMetadata": true,
    "experimentalDecorators": true
  },
  "include": ["apps/**/*.ts"],
  "exclude": ["node_modules", "dist"]
}

为什么需要这个文件:NestJS 项目根 tsconfig.json 没显式列 types。当 ts-jest 编译 .spec.ts 时,TypeScript 不自动加载 @types/jest,会报 TS2593: Cannot find name 'describe'。独立 tsconfig.spec.json + types: ["jest", "node"] = 让测试环境独立、显式。

改 package.json 加 test script(在 scripts 段加 3 行):

"test": "jest",
"test:watch": "jest --watch",
"test:cov": "jest --coverage"

4.1 · 写 RolesGuard 测试

新建 apps/gateway/src/guards/roles.guard.spec.ts:

import { RolesGuard } from './roles.guard';
import { Reflector } from '@nestjs/core';
import { ExecutionContext } from '@nestjs/common';

describe('RolesGuard', () => {
  let guard: RolesGuard;
  let reflector: Reflector;

  beforeEach(() => {
    reflector = new Reflector();
    guard = new RolesGuard(reflector);
  });

  // mock ExecutionContext — 只给测试需要的字段
  function makeContext(userRolesHeader?: string): ExecutionContext {
    const headers: Record<string, string> = {};
    if (userRolesHeader) headers['x-user-roles'] = userRolesHeader;
    return {
      switchToHttp: () => ({
        getRequest: () => ({ headers }),
        getResponse: () => ({}),
      }),
      getHandler: () => function testHandler() {},
      getClass: () => class TestClass {},
    } as any;
  }

  it('allows when no @Roles metadata is set', () => {
    jest.spyOn(reflector, 'getAllAndOverride').mockReturnValue(undefined);
    expect(guard.canActivate(makeContext())).toBe(true);
  });

  it('allows when user has one of the required roles', () => {
    jest.spyOn(reflector, 'getAllAndOverride').mockReturnValue(['admin', 'editor']);
    expect(guard.canActivate(makeContext('admin,user'))).toBe(true);
  });

  it('denies when user role does not match', () => {
    jest.spyOn(reflector, 'getAllAndOverride').mockReturnValue(['admin']);
    expect(guard.canActivate(makeContext('guest'))).toBe(false);
  });

  it('denies when no x-user-roles header', () => {
    jest.spyOn(reflector, 'getAllAndOverride').mockReturnValue(['admin']);
    expect(guard.canActivate(makeContext())).toBe(false);
  });
});

4.2 · 写 ProxyService 测试

新建 apps/gateway/src/proxy/proxy.service.spec.ts:

import { ProxyService } from './proxy.service';
import { HttpClientService } from '../common/http-client/http-client.service';
import { HttpException } from '@nestjs/common';

describe('ProxyService', () => {
  let service: ProxyService;
  let mockHttpClient: jest.Mocked<HttpClientService>;
  let mockLogger: any;

  beforeEach(() => {
    mockHttpClient = { request: jest.fn() } as any;
    mockLogger = { info: jest.fn(), error: jest.fn() };
    service = new ProxyService(mockLogger, mockHttpClient);
  });

  it('forwards to correct downstream URL', async () => {
    mockHttpClient.request.mockResolvedValue({ ok: true });

    await service.forward('auth', 'POST', '/api/auth/login', { x: 1 });

    expect(mockHttpClient.request).toHaveBeenCalledWith(
      expect.objectContaining({
        method: 'POST',
        url: 'http://localhost:3004/api/auth/login',
        data: { x: 1 },
      })
    );
  });

  it('throws on unknown service', async () => {
    await expect(service.forward('unknown', 'GET', '/x')).rejects.toThrow(
      'Unknown service: unknown',
    );
  });

  it('wraps downstream error as HttpException with status', async () => {
    const downstreamErr = {
      response: { status: 401, data: { message: 'Invalid credentials' } },
    };
    mockHttpClient.request.mockRejectedValue(downstreamErr);

    await expect(
      service.forward('auth', 'POST', '/api/auth/login', {}),
    ).rejects.toBeInstanceOf(HttpException);
  });

  it('rethrows plain error when no response field', async () => {
    mockHttpClient.request.mockRejectedValue(new Error('ECONNREFUSED'));

    await expect(service.forward('auth', 'GET', '/x')).rejects.toThrow(
      'ECONNREFUSED',
    );
  });
});

4.3 · 写 HttpClientService 测试

新建 apps/gateway/src/common/http-client/http-client.service.spec.ts:

import { HttpClientService } from './http-client.service';
import { HttpService } from '@nestjs/axios';
import { of } from 'rxjs';

describe('HttpClientService', () => {
  let service: HttpClientService;
  let mockHttp: jest.Mocked<HttpService>;

  beforeEach(() => {
    mockHttp = { request: jest.fn() } as any;
    const mockRequest = { id: 'test-req-id-123', headers: {} } as any;
    service = new HttpClientService(mockHttp, mockRequest);
  });

  it('auto-adds x-request-id header from current REQUEST', async () => {
    mockHttp.request.mockReturnValue(of({ data: { ok: true } } as any));

    await service.request({ method: 'GET', url: 'http://x.com/y' });

    expect(mockHttp.request).toHaveBeenCalledWith(
      expect.objectContaining({
        method: 'GET',
        url: 'http://x.com/y',
        headers: expect.objectContaining({
          'x-request-id': 'test-req-id-123',
          'Content-Type': 'application/json',
        }),
      }),
    );
  });

  it('does NOT add x-request-id when request has no id', async () => {
    (service as any).currentRequest = { headers: {} };
    mockHttp.request.mockReturnValue(of({ data: {} } as any));

    await service.request({ method: 'GET', url: 'http://x.com/y' });

    const call = mockHttp.request.mock.calls[0][0] as any;
    expect(call.headers).not.toHaveProperty('x-request-id');
  });

  it('preserves caller-provided headers', async () => {
    mockHttp.request.mockReturnValue(of({ data: {} } as any));

    await service.request({
      method: 'POST',
      url: 'http://x.com/y',
      headers: { Authorization: 'Bearer xyz' },
    });

    expect(mockHttp.request).toHaveBeenCalledWith(
      expect.objectContaining({
        headers: expect.objectContaining({
          Authorization: 'Bearer xyz',
          'x-request-id': 'test-req-id-123',
        }),
      }),
    );
  });
});
