1. imports / exports 实战回顾(LR-0012 Q3 + Q5 + Q6 + Q7)

LR-0012 写过 7 个相关问答。快速回顾最关键的 3 条:

关键回顾(单独成块,免得扫过去)

① Service 在它归属业务域的 module 里(CartService → CartModule.providers,不是 AppModule)
② AppModule 必须显式 import 子 module — exports 不是 transitive,AppModule 看不到 BusinessModule 导入的 CartService
③ module 不在 AppModule.imports = 死代码 — routes / providers / exports 全部失效

2. @Global() — 真正全局的 service

@Global() 装饰器让 module 的 exports 全 app 可见 — 不需要在每个 module 的 imports 里列。

@Global()                          // ← 加这一行
@Module({
  providers: [ConfigService],
  exports: [ConfigService],
})
export class ConfigModule {}

任何 module 都能直接 inject ConfigService — 不需要在 imports 列 ConfigModule。

什么时候用 @Global()(重要)

✅ 用:ConfigService / LoggerService / DateUtil / 加密 key — 全 app 通用,到处用
❌ 不用:BusinessService / CartService / OrderService — 业务服务,只在一两个 module 用

判断标准:"我能不能想象这个 service 在 80% 的 module 里被用到?" 是 → @Global,否 → 不加

你的 nest-search 当前状态:ConfigModule 和 LoggerModule 已经设了 isGlobal(注意 ConfigModule.forRoot 的 isGlobal 不是 @Global 装饰器,而是 ConfigModule 自己的机制 — 等价)。

3. DynamicModule — 可配置参数的 module

普通 module 是装饰器装饰一个 class:

@Module({...})
export class TypeOrmModule {}

DynamicModule 是返回对象(不是 class instance):

@Module({})
export class LoggerModule {
  static forRoot(config: LoggerConfig): DynamicModule {
    // 根据 config 动态生成 providers / exports
    return {
      module: LoggerModule,
      providers: [
        { provide: 'LOGGER_CONFIG', useValue: config },
        PinoLogger,
      ],
      exports: [PinoLogger],
      global: true,                 // ← 也可以动态决定是否全局
    };
  }
}

// 用法:
@Module({
  imports: [LoggerModule.forRoot({ level: 'info', transport: 'pino-pretty' })],
})
export class AppModule {}

为什么需要:

  • 配置可参数化(LoggerModule.forRoot(config))
  • 异步加载(返回 Promise)
  • 多实例(测试 / 生产用不同配置)

你的 nest-search 当前状态:LoggerModule.forRoot / ConfigModule.forRoot / ThrottlerModule.forRoot 都是 DynamicModule 模式 — 整个 NestJS 生态的"配置型 module"都用这个。

4. forwardRef — 解决循环依赖

两个 class 互相 inject 时,DI 容器不知道先 new 哪个:

class CartService {
  constructor(private orderService: OrderService) {}   // ← A 依赖 B
}

class OrderService {
  constructor(private cartService: CartService) {}   // ← B 依赖 A
}

运行时 NestJS 报错:Circular dependency detected。

修法:forwardRef

import { forwardRef, Inject } from '@nestjs/common';

class CartService {
  constructor(
    @Inject(forwardRef(() => OrderService))    // ← 告诉 DI "先实例化 Cart,Order 之后再注入"
    private orderService: OrderService,
  ) {}
}

class OrderService {
  constructor(
    @Inject(forwardRef(() => CartService))
    private cartService: CartService,
  ) {}
}
什么时候用 forwardRef

✅ 用:真正不可避免的循环依赖(A 用 B,B 用 A,删不掉)
❌ 不要用:"模块拆得不好"的擦屁股 — 正确做法是重构 module 边界,让依赖单向

你的 nest-search 目前没循环依赖(dependencies 都是单向的)。

5. 动手 · gateway 拆 feature module(0012 金样本)

你 nest-search 当前状态:AppController 20 个 handler 全堆一起,AppModule 5+ provider 全平铺 — 这是"demo 状态",不是"production"。

这次把它拆成 4 个 feature module + 1 个 shared module:

AppModule (composition root) ├── imports: │ ├── ConfigModule.forRoot({ isGlobal: true }) ← 已装 │ ├── LoggerModule.forRoot({ ... }) ← 已装 │ ├── ThrottlerModule.forRoot([...]) ← 已装 │ ├── HttpClientModule ← 0010 加的(shared HTTP) │ ├── HealthModule ← 已装 │ ├── ProxyModule (@Global) ← 0012 新加(shared ProxyService) │ ├── AuthProxyModule ← 0012 新拆 │ ├── SearchProxyModule ← 0012 新拆 │ ├── SyncProxyModule ← 0012 新拆 │ └── FormProxyModule ← 0012 新拆(本节不做,留 follow-up) └── providers: ├── (顶层守卫/过滤器)CasGuard / ApiKeyGuard / ThrottlerGuard / RolesGuard ├── AllExceptionsFilter / TimingInterceptor / LifecycleProbeService

4 个 feature module 拆出来后,AppModule 就只剩"组合" — 这是 NestJS 推荐的"composition root"模式。

5.1 · 新建 ProxyModule(shared,@Global)

ProxyService 在所有 feature module 都用 — 抽到共享 module + @Global,避免每个 module 都 import。

新建 apps/gateway/src/proxy/proxy.module.ts:

import { Global, Module } from '@nestjs/common';
import { ProxyService } from './proxy.service';
import { HttpClientModule } from '../common/http-client/http-client.module';

@Global()                                  // ← exports 全 app 可见
@Module({
  imports: [HttpClientModule],             // ← 必须 import!@Global 不等于"看得见所有 module 的 provider"
  providers: [ProxyService],
  exports: [ProxyService],
})
export class ProxyModule {}

⚠️ 关键:@Global() 只让你的 exports 全 app 可见,你自己的 imports 还得列。ProxyModule 需要 HttpClientService(因为 ProxyService 构造注入),所以必须 imports: [HttpClientModule]。漏写这个 = 启动 UnknownDependenciesException。

5.2 · 新建 AuthProxyController(5 个 auth 路由搬过来)

新建 apps/gateway/src/auth-proxy/auth-proxy.controller.ts:

import { Body, Controller, Get, Post, Req } from '@nestjs/common';
import { Request } from 'express';
import { ApiTags, ApiOperation, ApiResponse } from '@nestjs/swagger';
import { Throttle } from '@nestjs/throttler';
import { LoginDto } from '../common/dto/login.dto';
import { RegisterDto } from '../common/dto/register.dto';
import { ProxyService } from '../proxy/proxy.service';

@ApiTags('Auth 代理')
@Controller('api/auth')
export class AuthProxyController {
  constructor(private readonly proxyService: ProxyService) {}

  @ApiOperation({ summary: "用户注册" })
  @Post('register')
  async register(@Body() body: RegisterDto) {
    return this.proxyService.forward('auth', 'POST', '/api/auth/register', body);
  }

  @ApiOperation({ summary: "用户登录" })
  @ApiResponse({ status: 200, description: "登录成功" })
  @ApiResponse({ status: 401, description: "凭证错" })
  @ApiResponse({ status: 429, description: "请求过于频繁" })
  @Throttle({ default: { limit: 5, ttl: 60_000 } })
  @Post('login')
  async login(@Body() body: LoginDto) {
    return this.proxyService.forward('auth', 'POST', '/api/auth/login', body);
  }

  @ApiOperation({ summary: "校验 token" })
  @Post('validate')
  async validate(@Body() body: any) {
    return this.proxyService.forward('auth', 'POST', '/api/auth/validate', body);
  }

  @ApiOperation({ summary: "登出" })
  @Post('logout')
  async logout() {
    return this.proxyService.forward('auth', 'POST', '/api/auth/logout');
  }

  @ApiOperation({ summary: "获取当前用户信息" })
  @Get('me')
  async me(@Req() req: Request) {
    return this.proxyService.forward('auth', 'GET', '/api/auth/me', undefined, {
      authorization: req.headers.authorization || '',
    });
  }
}

5.3 · 新建 AuthProxyModule(composes controller + provider)

新建 apps/gateway/src/auth-proxy/auth-proxy.module.ts:

import { Module } from '@nestjs/common';
import { AuthProxyController } from './auth-proxy.controller';

@Module({
  controllers: [AuthProxyController],   // ← controller 自动注册,5 个 routes 暴露
  // providers: []                       ← 不需要,ProxyService 是 @Global 自动可见
})
export class AuthProxyModule {}

关键:AuthProxyModule 不需要 imports: [ProxyModule],因为 ProxyModule 是 @Global。这是用 @Global 的好处。

5.4 · 改 AppModule + 删 AppController 的 5 个 auth 路由

打开 apps/gateway/src/app.module.ts,加 import + imports 加 AuthProxyModule:

import { AuthProxyModule } from './auth-proxy/auth-proxy.module';
import { ProxyModule } from './proxy/proxy.module';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    HttpClientModule,
    LoggerModule.forRoot({ ... }),
    ThrottlerModule.forRoot([...]),
    HealthModule,
    ProxyModule,                       // ← 新加,@Global 让其他 module 自动可见
    AuthProxyModule,                   // ← 新加
  ],
  ...
})
export class AppModule {}

打开 apps/gateway/src/app.controller.ts,删 5 个 auth handler (register / login / validate / logout / me)。

5.5 · 验证(从外部看不出区别)

重构后端,5 个 auth 路由应该完全一样工作:

curl -i -X POST -H "X-API-Key: ds_key_123" -H "Content-Type: application/json" -d '{"username":"a","password":"xxxxxx"}' http://localhost:3000/api/auth/login

期望 401(账号不存在),status code / requestId 跨服务追踪一切照旧。

用户视角看不出任何区别。但代码层面:AppController 短了 60 行,AppModule 简洁了,每个 feature module 可以独立测 / 独立重构 / 独立部署(未来微服务化)。
