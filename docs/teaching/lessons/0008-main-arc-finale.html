2. 跨服务追踪 — 当前痛点

考虑一个真实的排查场景:用户报"我登录失败",你要查"这条请求经过了哪些服务、每步做了什么"。

现在你的 gateway 日志里有 requestId=abc-123。但当你 grep "abc-123" auth-service.log 时 — **啥都没有**。因为 auth-service 自己生成了一个新的 reqId(requestId=def-456),两个日志无法关联。

修法:gateway 在转发请求给 auth-service 时,加一个 x-request-id: abc-123 HTTP 头。auth-service 的 nestjs-pino(0005 装的那个)会检测这个头,如果存在就用它,否则才生成新的。

之后两边日志用同一个 ID,你就能在两个进程里 grep 同一个 ID 看完整轨迹了。

这跟 OpenTelemetry 的 traceparent 头思路一致 — 业界标准,我们这里手动实现最简版。

3. DTO 严格化 — 当前的 gateway 是个"骗子"

看现在的 app.controller.ts:

@Post('api/auth/login')
async login(@Body() body: any) {
  return this.proxyService.forward('auth', 'POST', '/api/auth/login', body);
}

@Body() body: any 意味着:任何 JSON 都能进来,不做任何校验。所以:

  • 前端发 {"email": "a@b.com", "password": "x"} → 字段名错的,网关不拦,转发给 auth-service,auth-service 返 400
  • 前端发 {"username": "a", "password": ""} → password 是空字符串,网关不拦,转发给 auth-service
  • 前端发 {"foo": "bar"} → 完全没字段,网关不拦,转发给 auth-service

每个错误请求都要走完整个调用链才被发现 — **在网关层就能拦的事,白白浪费了下游服务的处理时间**。

DTO 严格化 = 在网关层用 class-validator 装饰器描述字段约束,NestJS 的 ValidationPipe 自动校验,失败直接 400,根本不转发到下游。

前端同事:Swagger UI 现在能显示真实字段(`username: string, password: string, minLength 6`),不再是 `body: any`。

4. 动手 · 6 步

4.1 · main.ts 装 ValidationPipe

打开 apps/gateway/src/main.ts,在 app.enableCors(...) 之后加:

import { ValidationPipe } from '@nestjs/common';

// ... 现有代码
app.enableCors({ ... });
app.enableShutdownHooks();
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,    // 自动剔除没在 DTO 里声明的字段
  transform: true,    // 自动把 plain object 转成 DTO class instance
}));

装上之后,所有带 DTO 的 handler 都会自动校验。

4.2 · 新建 LoginDto

新建 apps/gateway/src/common/dto/login.dto.ts:

import { IsString, MinLength } from 'class-validator';

export class LoginDto {
  @IsString()
  @MinLength(1, { message: 'username 不能为空' })
  username: string;

  @IsString()
  @MinLength(6, { message: 'password 至少 6 位' })
  password: string;
}

4.3 · 新建 RegisterDto

新建 apps/gateway/src/common/dto/register.dto.ts:

import { IsEmail, IsString, MinLength, IsOptional } from 'class-validator';

export class RegisterDto {
  @IsString()
  @MinLength(1, { message: 'username 不能为空' })
  username: string;

  @IsString()
  @MinLength(6, { message: 'password 至少 6 位' })
  password: string;

  @IsOptional()
  @IsEmail({}, { message: 'email 格式不对' })
  email?: string;
}

4.4 · AppController 替换 @Body() body: any

打开 apps/gateway/src/app.controller.ts,加 import + 改两个 handler:

import { LoginDto } from './common/dto/login.dto';
import { RegisterDto } from './common/dto/register.dto';

@ApiOperation({ summary: "用户登录(代理到 auth-service)" })
@ApiResponse({ status: 200, description: "登录成功" })
@ApiResponse({ status: 400, description: "请求体参数校验失败" })
@ApiResponse({ status: 401, description: "凭证错" })
@ApiResponse({ status: 429, description: "请求过于频繁" })
@Throttle({ default: { limit: 5, ttl: 60_000 } })
@Post("api/auth/login")
async login(@Body() body: LoginDto) {   // ← 改: any → LoginDto
  return this.proxyService.forward("auth", "POST", "/api/auth/login", body);
}

@ApiOperation({ summary: "用户注册(代理到 auth-service)" })
@ApiResponse({ status: 201, description: "注册成功" })
@ApiResponse({ status: 400, description: "参数校验失败" })
@Post("api/auth/register")
async register(@Body() body: RegisterDto) {   // ← 改: any → RegisterDto
  return this.proxyService.forward("auth", "POST", "/api/auth/register", body);
}

其他 5 个 handler (validate / logout / me / 各种 sync / search / form) **不动** — 它们要么没 body,要么 body 是路径参数(不是 DTO 场景)。**只改 2 个最常用的 POST**。

4.5 · ProxyService 自动转发 x-request-id

打开 apps/gateway/src/proxy/proxy.service.ts,改 constructor + forward():

import { Inject, Injectable, HttpException } from '@nestjs/common';
import { REQUEST } from '@nestjs/core';
import { Request } from 'express';
import axios, { Method } from 'axios';
import { InjectPinoLogger, PinoLogger } from 'nestjs-pino';

const SERVICE_MAP: Record<string, string> = {
  sync: process.env.SYNC_SERVICE_URL || 'http://localhost:3001',
  search: process.env.SEARCH_SERVICE_URL || 'http://localhost:3002',
  form: process.env.FORM_SERVICE_URL || 'http://localhost:3003',
  auth: process.env.AUTH_SERVICE_URL || 'http://localhost:3004',
};

@Injectable()
export class ProxyService {
  constructor(
    @InjectPinoLogger(ProxyService.name) private readonly logger: PinoLogger,   // ← 保留(0005 装的)
    @Inject(REQUEST) private readonly request: Request,                            // ← 新增
  ) {}

  async forward(
    service: string,
    method: Method,
    path: string,
    body?: any,
    headers?: Record<string, string>,
  ) {
    const baseUrl = SERVICE_MAP[service];
    if (!baseUrl) {
      throw new Error(`Unknown service: ${service}`);
    }

    const url = `${baseUrl}${path}`;
    this.logger.info(`Proxying ${method} ${path} → ${service}-service`);

    // ✅ 自动把当前请求的 reqId 加到转发头里
    const requestId = (this.request as any).id;   // nestjs-pino 注入的
    const forwardedHeaders = {
      'Content-Type': 'application/json',
      ...(requestId ? { 'x-request-id': requestId } : {}),
      ...headers,
    };

    try {
      const response = await axios({
        method,
        url,
        data: body,
        headers: forwardedHeaders,
        timeout: 30000,
      });

      return response.data;
    } catch (error: any) {
      if (error.response) {
        this.logger.error(`Downstream error: ${error.response.status} ${error.response.data?.message}`);
        throw new HttpException(error.response.data, error.response.status);
      }
      this.logger.error(`Proxy error: ${error.message}`);
      throw error;
    }
  }
}

关键点: @Inject(REQUEST) 拿到当前请求对象,nestjs-pino 之前已经给 req.id 赋值。我们把它加到 headers,下游服务就能用同一个 ID。
