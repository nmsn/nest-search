1. Provider 的 4 种写法 — 决定"实例怎么来"

上节课用了最简单的一种:

// 第 1 种:class(直接列)
providers: [CartService]
// 解读: NestJS 自己 new CartService() + 自动注入依赖

实际上 NestJS 提供了 4 种写法,每种背后是"实例怎么来"的 4 种决策:

写法实例来源典型场景
providers: [X]框架 new + 自动注入普通 service(最常见)
{ provide: 'T', useValue: v }直接给一个值常量、配置、第三方实例
{ provide: A, useClass: B }new B 但 token 是 A动态选实现、interface 注入
{ provide: 'T', useFactory: fn, inject: [...] }调 fn 算出来运行时决策、动态创建

每种写法的实战

写法 1:class(已用 30+ 次)

providers: [CartService]   // 框架 new + 自动注入依赖

写法 2:useValue(给常量 / 第三方实例)

providers: [
  CartService,
  { provide: 'CART_OPTIONS', useValue: { currency: 'USD', tax: 0.08 } },
  //                            ↑ 这个值就当 instance 用了
]

// 用:
@Injectable()
export class CartService {
  constructor(
    @Inject('CART_OPTIONS') private options: { currency: string; tax: number },
  ) {}
}

写法 3:useClass(动态选实现)

// 接口
abstract class CacheService { abstract get(key: string): Promise<any>; }

// 实现 A
class RedisCacheService extends CacheService { /* ... */ }

// 实现 B
class MemoryCacheService extends CacheService { /* ... */ }

// 在 module 里"绑定"
@Module({
  providers: [
    { provide: CacheService, useClass: process.env.REDIS_URL ? RedisCacheService : MemoryCacheService },
    //                     ↑ 运行时决定用哪个
  ],
})
export class CacheModule {}

// 用(只认 interface,不认具体类):
@Injectable()
export class CartService {
  constructor(private cache: CacheService) {}   // ← interface
}

写法 4:useFactory(运行时计算)

providers: [
  {
    provide: 'DATABASE_CONNECTION',
    useFactory: (config: ConfigService) => {
      return new Pool({   // 任何"需要复杂初始化"的对象
        host: config.get('DB_HOST'),
        port: config.get('DB_PORT'),
      });
    },
    inject: [ConfigService],   // ← useFactory 的依赖
  },
]

2. useExisting — 同一 instance,不同 token

// 接口 + 实现
abstract class ILogger { abstract log(msg: string): void; }
@Injectable() class PinoLogger extends ILogger { /* ... */ }

@Module({
  providers: [
    PinoLogger,
    { provide: 'ILogger', useExisting: PinoLogger },
    //            ↑ 跟 PinoLogger 是同一个 instance
  ],
  exports: ['ILogger'],
})
export class CoreModule {}

// 用:
@Injectable()
export class CartService {
  constructor(@Inject('ILogger') private logger: ILogger) {}   // interface 注入
}

useClass 是"new 一个新 instance",useExisting 是"指向已有 instance"。后者省一次 new,语义更清晰。

3. ModuleRef — 框架拿不到时手动取

大多数情况,NestJS 自动注入就够了。但有 3 种场景需要 ModuleRef:

  1. 动态选实现:moduleRef.get(SERVICE_A, { strict: false }) — 根据配置拿不同 service
  2. 条件注入:if (feature) moduleRef.get(FeatureService)
  3. 测试 mock:用 ModuleRef 取 instance 后手动调 method(避开 nestjs-testing 框架)
import { ModuleRef } from '@nestjs/core';

@Injectable()
export class CartService {
  constructor(private moduleRef: ModuleRef) {}

  async checkout(userId: string) {
    // 条件注入:有 cache 就用,没有就跳过
    const cache = this.moduleRef.get(CacheService, { strict: false });
    if (cache) {
      const items = await cache.get(`cart:${userId}`);
      if (items) return items;
    }
    // 真正查 DB
    return this.db.query(...);
  }
}

不要过度使用 — 大多数情况自动注入就够,ModuleRef 是"框架拿不到时的兜底"。

4. Provider Scope — singleton / request / transient

这是 0010 最重要的概念。Scope 决定 instance 的生命周期:

Scope什么时候 new内存典型场景
singleton(默认)整个 app 启动时 1 次1 个 instance绝大多数 service
request每个 HTTP 请求 1 个N 个(N=并发请求数)需要"每个请求独立状态"的 service
transient每次注入都 new每次注入 +1几乎不用,有副作用隔离需求时

使用方式

// 1. singleton(默认,什么都不写)
@Injectable()
export class CartService {}

// 2. request scope
@Injectable({ scope: Scope.REQUEST })
export class RequestScopedService {}

// 3. transient scope
@Injectable({ scope: Scope.TRANSIENT })
export class TransientService {}

陷阱 1:request scope 会让所有依赖它的人变 request scope

传染性:

@Injectable({ scope: Scope.REQUEST })
class FooService {}

@Injectable()
class BarService {  // ← 也会变 REQUEST scope,因为依赖了 FooService
  constructor(private foo: FooService) {}
}

实际后果:每个 HTTP 请求都会 new BarService(本来 singleton 现在变 request)。**频繁 new 拖慢响应**。

陷阱 2:request scope 跟 Gate 是冲突的

你 nest-search 当前 global Guard(CasGuard, ApiKeyGuard, ThrottlerGuard)是 singleton。如果它们注入了 request scope 的 service,Guard 启动时就会因为"没 request context"报错。

要解决,Guard 也要变 request scope,或者 Guard 不用 request scope 的 service。**这是为什么默认 singleton 是好选择**。

陷阱 3:transient 频繁 new 拖慢 + 内存涨

transient 的 service 每次 inject 都 new。**1000 个请求 × 5 个 transient 依赖 = 5000 次 new**。如果 service 构造里有 IO 操作(读 config / 拉 connection),性能雪崩。

什么时候用 request / transient?

场景用
服务需要"当前用户信息"做决策(每个请求不同)request + 用 CLS(Continuation Local Storage)读
服务构造里读 request body / header(必须有 request context)request
其他 99% 情况singleton(默认)

关键事实: 0008 那个 keep-alive 阻塞 dispose 的 bug,根因是 disableShutdownHooks + keep-alive 连接没断,不是 scope 问题。但 scope 选错会引发类似"实例不释放"或"每次请求 new 太慢"的 bug。

5. 动手 · HttpClientService 抽离

上节课 0008 留的"手写 forwardedHeaders" 是**反模式** — 工业级做法是用 interceptor / useFactory 集中处理。这次把它清理掉。

5.1 · 新建 HttpClientService

新建 apps/gateway/src/common/http-client/http-client.service.ts:

import { Inject, Injectable } from '@nestjs/common';
import { HttpService } from '@nestjs/axios';
import { REQUEST } from '@nestjs/core';
import { Request } from 'express';
import { firstValueFrom } from 'rxjs';
import { AxiosRequestConfig } from 'axios';

@Injectable()
export class HttpClientService {
  constructor(
    private readonly http: HttpService,
    @Inject(REQUEST) private readonly request: Request,
  ) {}

  async request<T = any>(config: AxiosRequestConfig): Promise<T> {
    // 自动从当前 request 拿 requestId,加到 x-request-id 头
    const requestId = (this.request as any).id;
    const headers = {
      'Content-Type': 'application/json',
      ...config.headers,
      ...(requestId ? { 'x-request-id': requestId } : {}),
    };

    const response = await firstValueFrom(
      this.http.request<T>({ ...config, headers }),
    );
    return response.data;
  }
}

这个 service 集中做了 3 件事:① 用 @nestjs/axios(而不是裸 axios)② 自动加 x-request-id 头 ③ 把 Observable 转 Promise(更顺手)。

5.2 · 新建 HttpClientModule

新建 apps/gateway/src/common/http-client/http-client.module.ts:

import { Module } from '@nestjs/common';
import { HttpModule } from '@nestjs/axios';
import { HttpClientService } from './http-client.service';

@Module({
  imports: [HttpModule],   // ← HttpModule 是 @nestjs/axios 的 module
  providers: [HttpClientService],
  exports: [HttpClientService],
})
export class HttpClientModule {}

5.3 · ProxyService 改用 HttpClientService

打开 apps/gateway/src/proxy/proxy.service.ts,改 3 处:

  1. 删 axios / REQUEST 相关 import(改用 HttpClientService)
  2. constructor 改注入 HttpClientService
  3. forward() 删手写 forwardedHeaders

改完核心片段:

import { HttpException, Injectable } from '@nestjs/common';
import { Method } from 'axios';
import { InjectPinoLogger, PinoLogger } from 'nestjs-pino';
import { HttpClientService } from '../common/http-client/http-client.service';

@Injectable()
export class ProxyService {
  constructor(
    @InjectPinoLogger(ProxyService.name) private readonly logger: PinoLogger,
    private readonly httpClient: HttpClientService,   // ← 新注入
  ) {}

  async forward(service, method, path, body?, headers?) {
    const url = `${SERVICE_MAP[service]}${path}`;
    this.logger.info(`Proxying ${method} ${path} → ${service}-service`);

    try {
      // HttpClientService 自动加 x-request-id,ProxyService 不管
      return await this.httpClient.request({
        method,
        url,
        data: body,
        headers,
        timeout: 30000,
      });
    } catch (error) {
      if (error.response) {
        this.logger.error(`Downstream error: ${error.response.status} ${error.response.data?.message}`);
        throw new HttpException(error.response.data, error.response.status);
      }
      this.logger.error(`Proxy error: ${error.message}`);
      throw error;
    }
  }
}

代码短了 20 行(不用手写 forwardedHeaders 也不用 REQUEST 注入)。HttpClientService 集中处理 x-request-id。

5.4 · app.module.ts 注册 HttpClientModule

打开 apps/gateway/src/app.module.ts:

  1. 顶部加 import { HttpClientModule } from './common/http-client/http-client.module';
  2. 在 imports 数组加 HttpClientModule(放最上面,因为其他 module 都要用)
@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),

    HealthModule,
    ThrottlerModule.forRoot([...]),

  ...
