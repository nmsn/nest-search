1. 为什么是 Pino,不是 console.log

先看一个对比。同一个"请求出错了"事件,两种写法:

console.log(字符串)

console.error('[AllExceptions]', exception);
// 输出:
// [AllExceptions] Error: Invalid credentials
//     at AppController.login (...)
//     ...

Pino(结构化 JSON)

logger.error({ err: exception, requestId: 'abc-123' }, 'login failed');
// 输出:
// {"level":50,"time":...,"requestId":"abc-123",
//  "err":{"message":"Invalid credentials",...}}

字符串日志 vs JSON 日志,生产价值天差地别:

场景 console.log Pino JSON
查"requestId=abc-123 这个请求的所有日志" ❌ 没法 grep 字段,只能凭时间戳猜 ✅ jq 'select(.requestId=="abc-123")'
"5 分钟内有多少 500 错误?" ❌ 需要写正则,脆弱 ✅ jq 'select(.statusCode>=500)' | wc -l
接 ELK / Loki / Splunk ⚠️ 需要 grok 解析 ✅ 直接 ingest
按业务字段聚合(用户数 / 错误码) ❌ 几乎不可能 ✅ jq 'group_by(.userId) | length'

Pino 是 Node 生态里最快的 JSON logger([benchmarks](https://github.com/pinojs/pino/blob/master/docs/benchmarks.md)): 比 console.log 在高频日志场景下还快(因为它默认不格式化,直接 JSON.stringify 写流)。`nestjs-pino` 是 Pino 的 NestJS 官方风格集成包。

2. AsyncLocalStorage — requestId 怎么"跟住"你

先讲原理,这样你用 nestjs-pino 时不会觉得是魔法。

问题: 一个 HTTP 请求进入 NestJS,经过 Guard / Interceptor / Pipe / Controller / Service 一路调用,中间有 5+ 个 await、3 个 setTimeout、2 个 Promise 链。如果每个函数都要 log,你需要在每条 log 调用里手动传 requestId — 这会污染所有签名。

解法: Node 的 AsyncLocalStorage([MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/AsyncLocalStorage))。它是 V8 的"线程局部存储"等价物:

import { AsyncLocalStorage } from 'node:async_hooks';

const als = new AsyncLocalStorage<Map<string, string>>();

// 入口处"进入"上下文
als.run(new Map([['requestId', 'abc-123']]), () => {
  // 这里任何函数(同步/异步/await/setTimeout 都可以)
  // 都能拿到这个 requestId,不需要传参
  setTimeout(() => {
    const store = als.getStore();
    console.log(store?.get('requestId'));   // 'abc-123'
  }, 1000);
});

原理: V8 的 async_hooks 会在每次 microtask / Promise / setTimeout 创建时打"上下文快照",Node 把这个快照跟 Promise 绑定。同一 Promise 链上的所有函数都看到同一份 store — 不需要手动传参。

React 类比: 跟 `useContext` 是一回事 — Provider 在外层塞值,任何内层组件不用 prop drilling 就能拿到。Node 的"Provider" = `als.run()`,Node 的"useContext" = `als.getStore()`。

3. nestjs-pino 集成 — 一行配置搞定大半

`nestjs-pino` 已经替我们做完最难的"自动注入 requestId + AsyncLocalStorage"。你只需要在 AppModule 注册 LoggerModule:

import { LoggerModule } from 'nestjs-pino';
import { randomUUID } from 'node:crypto';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    LoggerModule.forRoot({
      pinoHttp: {
        level: process.env.LOG_LEVEL || 'info',
        genReqId: (req) => req.headers['x-request-id'] || randomUUID(),
        customProps: (req) => ({ requestId: req.id }),
        transport: process.env.NODE_ENV === 'production'
          ? undefined
          : { target: 'pino-pretty', options: { singleLine: true } },
      },
    }),
    ...
  ],
})

关键点:

  • genReqId: 优先用客户端传的 x-request-id 头,没有就生成 UUID。这样 跨服务转发时 requestId 会保留(proxy 加个头就行,留作 0006 扩展)
  • customProps: 把 reqId 暴露成 requestId 字段,所有日志都能拿到
  • transport: dev 环境用 pino-pretty 美化(单行,可读),prod 直接 JSON(机器可读)

默认行为: 每个 HTTP 请求进来,自动 log 一条 "request completed"(method / url / statusCode / durationMs)。你不用写一行 Interceptor 就有了访问日志。

4.4 · 替换 LifecycleProbeService 的 console.log

打开 apps/gateway/src/lifecycle/lifecycle-probe.service.ts,用 PinoLogger 替代 console.log:

import { Injectable, OnModuleInit, OnModuleDestroy, OnApplicationShutdown } from '@nestjs/common';
import { InjectPinoLogger, PinoLogger } from 'nestjs-pino';

@Injectable()
export class LifecycleProbeService implements OnModuleInit, OnModuleDestroy, OnApplicationShutdown {
  constructor(@InjectPinoLogger(LifecycleProbeService.name) private readonly logger: PinoLogger) {}

  onModuleInit() {
    this.logger.info('module dependencies resolved');
  }
  onModuleDestroy() {
    this.logger.info('closing connections (simulated)');
  }
  onApplicationShutdown(signal?: string) {
    this.logger.info({ signal }, 'flushing logs (simulated)');
  }
}

现在 log 输出是 JSON,带 context: "LifecycleProbeService" 字段,可以 grep。

4.5 · 升级 TimingInterceptor: tap → finalize + statusCode + Pino

打开 apps/gateway/src/interceptors/timing.interceptor.ts,完整重写:

import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable, finalize } from 'rxjs';
import { InjectPinoLogger, PinoLogger } from 'nestjs-pino';

@Injectable()
export class TimingInterceptor implements NestInterceptor {
  constructor(@InjectPinoLogger(TimingInterceptor.name) private readonly logger: PinoLogger) {}

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const start = performance.now();
    const req = context.switchToHttp().getRequest();
    return next.handle().pipe(
      finalize(() => {
        const durationMs = Number((performance.now() - start).toFixed(2));
        const statusCode = context.switchToHttp().getResponse().statusCode;
        this.logger.info({ method: req.method, url: req.url, statusCode, durationMs }, 'request completed');
      }),
    );
  }
}

两个关键修复:

  1. tap → finalize: 现在 4xx / 5xx 也能打 timing 日志(0004 漏的那个)
  2. 加 statusCode 字段: 你可以 jq 'select(.statusCode >= 500)' 找慢且失败的请求

4.6 · 升级 AllExceptionsFilter: 只 log 5xx + Pino

打开 apps/gateway/src/filters/all-exceptions.filter.ts,把 console.error 换成 PinoLogger,并加 statusCode 判断:

import { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus } from '@nestjs/common';
import { Request, Response } from 'express';
import { InjectPinoLogger, PinoLogger } from 'nestjs-pino';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  constructor(@InjectPinoLogger(AllExceptionsFilter.name) private readonly logger: PinoLogger) {}

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const status = exception instanceof HttpException
      ? exception.getStatus()
      : HttpStatus.INTERNAL_SERVER_ERROR;

    // ✅ 关键: 只 log 5xx,4xx 静默
    if (status >= 500) {
      this.logger.error({ err: exception, path: request.url, method: request.method }, 'unhandled exception');
    } else {
      this.logger.debug({ status, path: request.url }, 'client error (expected)');
    }

    const message = exception instanceof HttpException
      ? exception.getResponse()
      : 'Internal server error';

    response.status(status).json({
      statusCode: status,
      message: typeof message === 'string' ? message : (message as any).message || message,
      error: typeof message === 'string' ? message : (message as any).error || 'Error',
      timestamp: new Date().toISOString(),
      path: request.url,
    });
  }
}

4xx(401 / 400 等预期错误)走 debug 级,默认不显示;5xx(真崩了)走 error 级,带完整 stack。这是行业标准做法。
