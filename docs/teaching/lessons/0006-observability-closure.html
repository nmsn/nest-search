1. 为什么现在的 /health 是 bug

看 apps/gateway/src/app.controller.ts 里的 health():

@Get('health')
health() {
  return { status: 'ok', service: 'gateway', timestamp: new Date().toISOString() };
}

这个 endpoint **永远返回 200**,无论下面这些情况:

  • MySQL 挂了,gateway 没法 proxy 任何业务
  • auth-service 进程死了,gateway 的 /api/auth/* 全部 502
  • RabbitMQ 连接断了,所有事件流停了
  • 内存泄漏到 90% heap 占用

你的 gateway 在 K8s 里的状态会一直显示 "Ready" — 流量照打,然后客户端全 502。**这是 silent failure 的典型形态**。

现在的 /health

GET /health
→ 200 {"status":"ok"}
(无任何检查,谎报健康)

0006 之后

GET /health
→ 200 {
  "status": "ok",
  "info": {
    "auth_service": {"status": "up"},
    "memory_heap": {"status": "up"}
  }
}

GET /health
→ 503 (auth-service 挂了)
{"status": "error", ...}

2. K8s liveness vs readiness — 必须分清

两个 probe 用途完全不同,搞混了 service 会"卡死"或"被无限重启":

probe 问的问题 失败后果 用哪个 endpoint
liveness "我是不是死了 / 卡死了?" 重启 pod(K8s 觉得它不行了) /health/live — 只检查"进程在"
readiness "我能不能接新流量?" 摘出 Service endpoint(不重启,只是不接流量) /health 或 /health/ready — 检查下游依赖

经典坑: 把 liveness 接到了依赖检查的 endpoint 上,MySQL 抖一下,K8s 觉得 pod 死了,**直接重启** — 但重启 MySQL 也连不上,陷入"无限重启循环"。

3. @nestjs/terminus — HealthIndicator 模式

Terminus 给你一个 HealthCheckService,你传一个 indicator 数组,它跑每个 indicator,聚合成一个 JSON 响应:

@Get()
@HealthCheck()
check() {
  return this.health.check([
    (http)  => http.pingCheck('auth-service', 'http://localhost:3004'),
    (mem)   => mem.checkHeap('memory_heap', 200 * 1024 * 1024),
    (disk)  => disk.checkStorage('disk', { thresholdPercent: 0.9 }),
  ]);
}

每个 indicator 是一个函数,接受一个或多个 HealthIndicator 服务(http / mem / disk),返回一个 HealthIndicatorResult(成功或失败)。任意一个失败 → 整体 503。

Terminus 内置 indicator:

  • HttpHealthIndicator — pingCheck HTTP 端点
  • TypeORM / Mongoose / MikroOrm / Prisma — 数据库连接
  • MemoryHealthIndicator — checkHeap / checkRSS
  • DiskHealthIndicator — 磁盘空间

没有 Drizzle 内置 indicator(因为 Drizzle 不是"全功能 ORM"框架) — 但写一个自定义 indicator 也就 10 行(下面 §5.2 会做)。

4. Swagger 是什么、为什么必要

OpenAPI 是个"接口契约规范",Swagger 是它的可视化工具。装上之后:

  • 浏览器开 http://localhost:3000/api 看到所有 endpoint 的列表 + 字段
  • 每个 endpoint 标了"作用 / 参数 / 返回结构 / 错误码"
  • 前端可以在 Swagger UI 里"直接试"(点 Try it out)
  • 可以下载 openapi.json 给前端自动生成 client SDK(用 openapi-generator / orval 等)

没 Swagger 的世界: 前端同事看着你 controller 的源码"猜"字段名,经常猜错(尤其 email vs username 这种)。有了 Swagger,所有字段名都自动列出来。

5. 动手 · 6 个文件改动

这一节比 0005 简单: 大部分时间在写注解,核心代码就一个 HealthController。

5.1 · 装两个包

pnpm add -w @nestjs/terminus @nestjs/swagger

5.2 · 新建 HealthController

新建 apps/gateway/src/health/health.controller.ts:

import { Controller, Get } from '@nestjs/common';
import { HealthCheck, HealthCheckService, HttpHealthIndicator, MemoryHealthIndicator } from '@nestjs/terminus';
import { Public } from '../common/decorators';

@Controller('health')
export class HealthController {
  constructor(
    private readonly health: HealthCheckService,
    private readonly http: HttpHealthIndicator,
    private readonly memory: MemoryHealthIndicator,
  ) {}

  // liveness: 进程在就行
  @Public()
  @Get('live')
  @HealthCheck()
  liveness() {
    return this.health.check([(mem) => mem.checkHeap('memory_heap', 300 * 1024 * 1024)]);
  }

  // readiness: 进程在 + 下游能调到
  @Public()
  @Get()
  @HealthCheck()
  readiness() {
    return this.health.check([
      (http) => http.pingCheck('auth-service', 'http://localhost:3004', {
        // 接受 2xx / 3xx / 4xx 都算"活着",只有 5xx 才算挂了
        validateStatus: (status) => status >= 200 && status < 500,
      }),
      (mem) => mem.checkHeap('memory_heap', 200 * 1024 * 1024),
    ]);
  }
}

注意: @Public() 来自 0004 装的装饰器。K8s probe 不可能带 API key,必须跳过 Guard。

5.3 · 新建 HealthModule

新建 apps/gateway/src/health/health.module.ts:

import { Module } from '@nestjs/common';
import { TerminusModule } from '@nestjs/terminus';
import { HealthController } from './health.controller';

@Module({
  imports: [TerminusModule],
  controllers: [HealthController],
})
export class HealthModule {}

5.4 · 在 AppModule 注册 + 删旧 health()

打开 apps/gateway/src/app.module.ts,加 HealthModule 到 imports:

import { HealthModule } from './health/health.module';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    LoggerModule.forRoot({ ... }),
    HealthModule,   // ← 新加
  ],
  controllers: [AppController],
  ...
})

然后打开 apps/gateway/src/app.controller.ts,删掉旧 health() handler(被 HealthController 接管了):

// 删这些:
@Public()
@Get('health')
health() {
  return { status: 'ok', service: 'gateway', timestamp: new Date().toISOString() };
}

5.5 · main.ts 装 SwaggerModule

打开 apps/gateway/src/main.ts,在 app.listen(port) 之前加:

import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';

// ... 在 bootstrap() 里
const swaggerConfig = new DocumentBuilder()
  .setTitle('Nest-Search Gateway')
  .setDescription('API 网关 — 代理 auth / sync / search / form 4 个服务')
  .setVersion('1.0')
  .addApiKey({ type: 'apiKey', name: 'X-API-Key', in: 'header' }, 'X-API-Key')
  .build();
const document = SwaggerModule.createDocument(app, swaggerConfig);
SwaggerModule.setup('api', app, document);

await app.listen(port);

5.6 · 给 AppController 加 Swagger 注解

打开 apps/gateway/src/app.controller.ts,文件顶部加 @ApiTags,每个 handler 加 @ApiOperation + @ApiResponse。改完大概长这样:

import { ApiTags, ApiOperation, ApiResponse, ApiBody, ApiBearerAuth, ApiParam } from '@nestjs/swagger';
import { Public } from './common/decorators';

@ApiTags('Gateway · Auth 代理')
@Controller()
export class AppController {
  constructor(private readonly proxyService: ProxyService) {}

  @ApiOperation({ summary: '用户注册(代理到 auth-service)' })
  @ApiResponse({ status: 201, description: '注册成功' })
  @ApiResponse({ status: 400, description: '参数校验失败' })
  @Post('api/auth/register')
  async register(@Body() body: any) { ... }

  @ApiOperation({ summary: '用户登录(代理到 auth-service)' })
  @ApiResponse({ status: 200, description: '登录成功,返回 token' })
  @ApiResponse({ status: 401, description: '凭证错' })
  @Post('api/auth/login')
  async login(@Body() body: any) { ... }

  // ... 给所有 handler 类似加
}

注意: 我们不替换 @Body() body: any 为 DTO — 那是更大的重构(留 0007 / 0008 follow-up)。Swagger 能识别 any 类型,只是 docs 里看不到字段细节。

5.7 · 验证 3 件事

  1. 重启 pnpm start:gateway
  2. curl -i http://localhost:3000/health — 期望:200 + JSON body 含 info.auth_service 字段(如果 auth-service 跑着)。停掉 auth-service 再 curl,期望:503 + body 含 error.auth_service
  3. 浏览器开 http://localhost:3000/api — 期望:Swagger UI 列出所有 handler,带 summary / 响应码,点 "Try it out" 能直接 curl
  4. curl http://localhost:3000/api-json — 期望:下载 OpenAPI JSON spec

5.7 步骤 2 是这一节"金样本" — 看到 health check 真在检查下游,而不是 `return ok`,你会觉得"哦原来这才叫监控"。
