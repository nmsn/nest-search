1. 4 个切面 + 请求生命周期

NestJS 的请求生命周期里,有 4 个"切面"(aspect)可以插入你的逻辑:

HTTP Request │ ▼ [Middleware] ← Express 层(早就有了) │ ▼ [Guard(s)] ← "该不该进?" AuthGuard / RolesGuard │ ▼ [Interceptor.before] ← "请求前后包起来" Logging / Caching │ ▼ [Pipe] ← "参数转换 + 校验" ValidationPipe │ ▼ [Handler] ← "业务逻辑" │ ▼ [Interceptor.after] ← 同上,后半段 │ ▼ [Filter] ← "出错了怎么格式化" AllExceptionsFilter │ ▼ HTTP Response

每个切面负责不同的"横切关注"(cross-cutting concern)。

切面接口关心什么典型用途
GuardCanActivate请求该不该进入鉴权、角色校验
PipeTransform参数转换 / 校验ValidationPipe、ParseIntPipe
InterceptorNestInterceptor请求前后包起来Logging、Cache、Timeout
FilterExceptionFilter异常怎么格式化统一错误响应格式

2. Guard 深入 — 切面里最常用的

Guard 是 4 个切面里最常手写的,所以我们重点讲。其他 3 个有大量内置实现,理解就好。

2.1 Guard 接口

import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';

@Injectable()
export class MyGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    // 返回 true → 请求继续
    // 返回 false → 请求被拒(默认 403 Forbidden)
    // 抛异常 → 请求被拒(异常会被 Filter 处理)
    return true;
  }
}

2.2 ExecutionContext — 拿到请求的所有上下文

canActivate(context: ExecutionContext) {
  // 切换到 HTTP context(也可能是 RPC / WebSocket)
  const http = context.switchToHttp();

  // 拿请求 / 响应
  const request = http.getRequest<Request>();
  const response = http.getResponse<Response>();

  // 拿 handler metadata(哪个 method、哪个 controller)
  const handler = context.getHandler();
  const classRef = context.getClass();
}

2.3 Reflector — 读装饰器 metadata

import { Reflector } from '@nestjs/core';

@Injectable()
export class MyGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // 读 @Roles('admin', 'editor') 写的 metadata
    const roles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      context.getHandler(),  // 先看 method 上的 @Roles
      context.getClass(),    // 再看 class 上的 @Roles
    ]);
    // getAllAndOverride = "method 覆盖 class"
    return true;
  }
}

3. 动手 · 写 RolesGuard(0011 的金样本)

0009 lesson 你写了 @Roles('admin', 'editor') 但只写不读。这一节给它写 reader。

3.1 · 新建 roles.guard.ts

新建 apps/gateway/src/guards/roles.guard.ts:

import { CanActivate, ExecutionContext, Injectable } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { ROLES_KEY } from '../common/decorators/roles.decorator';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // 1. 读 @Roles metadata
    const requiredRoles = this.reflector.getAllAndOverride<string[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    // 2. 没有 @Roles = 不限制,放行
    if (!requiredRoles || requiredRoles.length === 0) return true;

    // 3. 从 request 拿 user roles(本节简化:从 header 读)
    const req = context.switchToHttp().getRequest();
    const userRolesHeader = req.headers['x-user-roles'];
    const userRoles: string[] = typeof userRolesHeader === 'string'
      ? userRolesHeader.split(',').map(r => r.trim())
      : [];

    // 4. 用户有任意一个所需角色即可
    return requiredRoles.some(role => userRoles.includes(role));
  }
}

为什么从 header 读 user roles:简化测试。生产应该从 JWT / session 读。0011 是 AOP 入门,JWT 解码是另一节课(0023)。

3.2 · 在 app.module.ts 注册为全局 Guard

打开 apps/gateway/src/app.module.ts,加 import + 在 providers 数组加一项:

import { RolesGuard } from './guards/roles.guard';

// ...providers 数组里加(放最后,跑得最晚):
{
  provide: APP_GUARD,
  useClass: RolesGuard,
},

放最后: global guard 按声明顺序跑。RolesGuard 在 CasGuard / ApiKeyGuard / ThrottlerGuard 之后跑,先过鉴权再过角色。

3.4 · 验证(用 script,绕过 CasGuard)

CasGuard / ApiKeyGuard 仍在跑,直接 curl 会被它挡。所以用 script 方式:直接构造 ExecutionContext mock,调 RolesGuard.canActivate()。

import { AppController } from '../app.controller';

// 用真实的 RolesGuard + 真实的 AppController
const guard = new RolesGuard(new Reflector());

// 构造一个 mock ExecutionContext
function makeContext(userRolesHeader?: string): ExecutionContext {

    switchToHttp: () => ({
      getRequest: () => ({

      getResponse: () => ({}),
      getNext: () => undefined,

    getHandler: () => AppController.prototype.syncFull,
    getClass: () => AppController,
    getArgs: () => [],
    getArgByIndex: () => undefined,

4. Pipe — 转换 + 校验(简版)

Pipe 有两个动作:transform(参数变形,如 "5" → 5)和 validate(参数校验,如必须是 email)。

// 内置 ParseIntPipe:把字符串 "5" 转成数字 5,失败抛 BadRequestException
@Param('id', ParseIntPipe) id: number

// 内置 ValidationPipe:校验 @Body 是不是 LoginDto
@UsePipes(new ValidationPipe({ whitelist: true, transform: true }))
@Post('login')
async login(@Body() body: LoginDto) {}

// 自定义 Pipe
@Injectable()
export class TrimPipe implements PipeTransform {
  transform(value: string) {
    return value?.trim();
  }
}

实战里 80% 用内置(ValidationPipe + ParseIntPipe)。手写 Pipe 是少数(自定义转换逻辑)。

5. Interceptor — 包裹 handler(简版)

Interceptor 像"洋葱皮" — 包在 handler 外面,能写 pre-hook 和 post-hook。

@Injectable()
export class TimingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const start = Date.now();
    return next.handle().pipe(
      tap(() => {
        const ms = Date.now() - start;
        console.log(`request took ${ms}ms`);
      }),
    );
  }
}

你 0004 装的 TimingInterceptor 就是这个模式。后续 0035(Observability)会扩展 — 加 response size、correlation id 等。

Interceptor 跟 Middleware 的区别:Middleware 是 Express 层(早于 NestJS),Interceptor 是 NestJS 层,能拿到 ExecutionContext(知道哪个 handler、哪个 class)。

6. Filter — 异常怎么格式化(简版)

Filter 专门处理异常。当 handler throw 异常时,Filter 接住,转成 HTTP response。

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse();

    const status = exception instanceof HttpException
      ? exception.getStatus()
      : 500;

    response.status(status).json({
      statusCode: status,
      message: 'something broke',
    });
  }
}

你 0002 装的 AllExceptionsFilter 是这个模式。@Catch() 不带参数 = 捕获所有异常。

Filter 跟 Interceptor 的区别:Interceptor 是"正常路径"(pre + post),Filter 是"异常路径"(异常发生才触发)。

7. 4 个切面的统一心智模型

把 4 个切面放一张图:

正常请求: Request → [Guard] "该不该进?" ← 鉴权 / 角色 → [Interceptor] "前后包一下" ← logging / cache → [Pipe] "参数转换" ← validate / parse → [Handler] "干正事" → [Filter?] (正常路径不触发) 异常请求: → [Guard throws] → Filter → [Handler throws] → Filter → [Pipe throws] → Filter → [Interceptor throws] → Filter

一张口诀:Guard 守门、Interceptor 包边、Pipe 转换、Filter 兜底。
