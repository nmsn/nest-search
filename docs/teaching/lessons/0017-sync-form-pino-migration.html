2. 动手 · sync-service 加 pino

2.1 · 改代码(10 行)

打开 apps/sync-service/src/app.module.ts,在 ConfigModule.forRoot 之后插入:

import { LoggerModule } from 'nestjs-pino';
import { randomUUID } from 'node:crypto';

// ...

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    LoggerModule.forRoot({
      pinoHttp: {
        level: process.env.LOG_LEVEL || 'info',
        genReqId: (req) => req.headers['x-request-id'] || randomUUID(),
        customProps: (req) => ({ requestId: req.id }),
        autoLogging: false,
      },
    }),
    SyncModule,
  ],
})

改动:加 2 个 import + 1 个 LoggerModule.forRoot 块。

2.2 · 实操 · 起 sync-service + 检查端口 + 看 log

第 1 步:先确认端口 3001 没被占:

lsof -i :3001 -P

无输出 = 端口空。如果有输出 → kill <PID>。

第 2 步:后台起 sync-service:

pnpm start:sync > /tmp/sync.log 2>&1 &
echo $! > /tmp/sync.pid
sleep 6

第 3 步:看启动 log:

grep "LoggerModule\|running on port" /tmp/sync.log

期望看到:

[InstanceLoader] LoggerModule dependencies initialized
Sync Service running on port 3001 (HTTP + RabbitMQ)

第 4 步:发个请求 + 看 log 是否有副作用:

curl -s http://localhost:3001/health -o /dev/null -w "status=%{http_code}\n"

第 5 步:杀进程:

kill $(cat /tmp/sync.pid) 2>/dev/null
# 双保险:用 lsof 强制清
lsof -ti :3001 -P | xargs kill -9 2>/dev/null
sync-service 同时跑 HTTP(3001)+ RabbitMQ consumer。如果只 kill nest start 父进程,RabbitMQ 连接可能残留。**lsof 兜底必加**。

4. 反向验证 · 故意改坏 pino 配置

光"装好"不算真懂。故意删一行,看会出什么问题。

4.1 · 删掉 genReqId 试试

在 form-service 的 app.module.ts 里,把:

genReqId: (req) => req.headers['x-request-id'] || randomUUID(),

改成:

// genReqId 删了

重启 form-service,curl 发请求看 log:

pnpm start:form > /tmp/form.log 2>&1 &
echo $! > /tmp/form.pid
sleep 6
curl -s -H "x-request-id: my-trace-abc" http://localhost:3003/health -o /dev/null
grep "my-trace-abc" /tmp/form.log     # 找不到!
grep "requestId" /tmp/form.log | head -2
kill $(cat /tmp/form.pid) 2>/dev/null
lsof -ti :3003 -P | xargs kill -9 2>/dev/null

观察:

  • x-request-id: my-trace-abc 这条 trace 在 form-service log 里**找不到了**
  • customProps 里的 requestId 字段变成 undefined(nestjs-pino 默认 fallback,但 requestId 不可用)

结论:genReqId 是把"上游 trace"接到"本服务 log"的关键桥。删了就跨服务追踪断。

恢复:把 genReqId 那行加回去。
