1. 为什么需要"跨服务迁移"

你 nest-search 现在 4 个后端服务。pino 结构化日志的覆盖:

服务pino 状态负责人
gateway✅ 0005 装好principles 轨道
auth-service✅ 主线收官时加主线
search-service❌ 裸 NestJS logger0016(本节)
sync-service❌ 裸 logger0017
form-service❌ 裸 logger0017

后果:用户在 search 失败时报错,gateway 知道 requestId(有 pino),search-service 不知道(只有 console.log)。要追"这次失败是哪个请求触发的",对不上号。

原则:nest-search 的 4 个后端服务 = 4 个独立进程 = 4 套日志。
要串起来,必须 都装 pino + 都透传 x-request-id。

2. 回顾 gateway 模式(0005)

gateway 装 pino 时用的代码(已经写好,你不用再写):

// apps/gateway/src/app.module.ts
import { LoggerModule } from 'nestjs-pino';
import { randomUUID } from 'node:crypto';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    LoggerModule.forRoot({
      pinoHttp: {
        level: process.env.LOG_LEVEL || 'info',
        genReqId: (req) => req.headers['x-request-id'] || randomUUID(),
        customProps: (req) => ({ requestId: req.id }),
        autoLogging: false,    // ← 不打每个 HTTP 请求(降噪)
      },
    }),
    // ...其他 module
  ],
})

4 个核心配置:

配置作用
level日志级别(env 控)
genReqId从 x-request-id 头拿;没有就生成 UUID
customProps每条日志都附 requestId 字段
autoLogging: false不打每个 HTTP 请求日志(显式 log 才打,降噪)

auth-service 用的是同一个模式(除了 autoLogging: true,因为 auth 路由少)。

3. 动手 · 把同一模式装到 search-service

3.1 · 改 apps/search-service/src/app.module.ts

在 ConfigModule.forRoot 后加 LoggerModule.forRoot,完全复制 gateway 模式:

import { Module, OnModuleInit } from '@nestjs/common';
import { ConfigModule } from '@nestjs/config';
import { LoggerModule } from 'nestjs-pino';
import { randomUUID } from 'node:crypto';
import { ElasticsearchModule } from './elasticsearch/elasticsearch.module';
import { ElasticsearchService } from './elasticsearch/elasticsearch.service';
import { SearchModule } from './search/search.module';
import { initIndices } from './elasticsearch/elasticsearch.init';

@Module({
  imports: [
    ConfigModule.forRoot({ isGlobal: true }),
    // ← 0016: 对齐 gateway 0005 模式 — pino + 跨服务 requestId 透传
    LoggerModule.forRoot({
      pinoHttp: {
        level: process.env.LOG_LEVEL || 'info',
        genReqId: (req) => req.headers['x-request-id'] || randomUUID(),
        customProps: (req) => ({ requestId: req.id }),
        autoLogging: false,
      },
    }),
    ElasticsearchModule,
    SearchModule,
  ],
})
export class AppModule implements OnModuleInit {
  constructor(private readonly esService: ElasticsearchService) {}

  async onModuleInit() {
    await initIndices(this.esService);
  }
}

改动量:1 个 import + 1 个 LoggerModule.forRoot 块 ≈ 10 行新增。没有改业务逻辑。

4. 副线 2 的统一心智模型

0016 + 0017 + 0018(把 sync / form 也装上)走完后,nest-search 4 个服务会完全一致:

原则轨道 (0009-0012)

把 1 个服务做到"完整"

gateway 是样板

副线 2 (0016-0018)

把"完整"复制到 N 个服务

其他 3 个服务对齐 gateway

经验法则:

  • 每改一个新服务 = 打开 gateway 对比 — 看哪些 module / config 已经装了
  • 新功能先在 gateway 跑通 → 复制到其他服务
  • 复制时只改必要差异(端口 / 数据库名 / 业务 module),不改 pino 配置
