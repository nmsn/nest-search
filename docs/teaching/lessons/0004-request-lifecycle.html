1. 5 阶段顺序图 — 长期记忆版

0002 §2 讲过 5 阶段,这节课给完整版,加上"谁先谁后"的精确顺序。

请求进入 │ ▼ [1] Middleware (Express 层级) │ ▼ [2] Guard(s) (按声明顺序,先 APP_GUARD 后 @UseGuards) │ ▼ [3] Interceptor(s) (pre-hook,按全局 → 路由) │ ▼ [4] Pipe(s) (对 @Param / @Query / @Body 转换 + 校验) │ ▼ [5] Controller.handler │ ▼ [5] Service(s) (handler 内部调用) │ ▼ [5] Interceptor(s) (post-hook,按路由 → 全局 — 反序) │ ▼ [4] Filter(s) (异常时接管,否则跳过) │ ▼ HTTP Response

三条铁律:

  1. Guard 失败 = 立即拒绝,后面 4 阶段都不会跑
  2. Interceptor 包裹 handler — pre-hook 在 handler 前跑,post-hook 在 handler 后跑(反序)
  3. Filter 是"出错的兜底" — 没异常就不出现

2. 拆开装饰器的黑盒

你之前看到的 @Controller()、@Injectable()、@Module() 看着像 TypeScript 语法糖,**其实不是**。它们是依赖 reflect-metadata 这个 polyfill 的真实"挂载"操作。

看一段真实代码:

import { SetMetadata } from '@nestjs/common';

export const IS_PUBLIC_KEY = 'isPublic';
export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);

SetMetadata(key, value) 的实现就一行:

// 来自 @nestjs/common
export const SetMetadata = <K = string, V = any>(metadataKey: K, metadataValue: V) =>
  (target: object, key?: any, descriptor?: any) => {
    Reflect.defineMetadata(metadataKey, metadataValue, descriptor.value);  // ← 真身
  };

看到了吗?@SetMetadata('isPublic', true) 实际上调用的是 Reflect.defineMetadata('isPublic', true, fn) — **直接写到了这个 method 的元数据槽里**。`reflect-metadata` polyfill 把每个函数对象都扩展出一个隐藏的"metadata 槽",可以挂任意键值对。

读的时候反过来:

import { Reflector } from '@nestjs/core';

@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      context.getHandler(),   // 先看 method 上的 @Public
      context.getClass(),     // 再看 class 上的 @Public
    ]);
    if (isPublic) return true;   // ← 关键:命中就放行
    // ... 原有 API key 验证逻辑
  }
}

所以 NestJS "装饰器元数据"的本质就是:

   装饰器          运行时              Reflector
   @Public()   ──▶  Reflect.define  ──▶  Reflect.get
       │              ('isPublic', true)        │
       │                  │                     │
       ▼                  ▼                     ▼
   写在 method       存到 method           在 Guard 里
   上方              的隐藏 slot           读出来

三句话总结:

  • 不是魔法 — 是标准 ES Reflect API,只是要在 tsconfig.json 开启 "emitDecoratorMetadata": true
  • 全靠 polyfill — Node 原生 V8 不支持 metadata,必须 import 'reflect-metadata'(NestJS 在 main.ts 隐式加载了)
  • Reflector 是 NestJS 的读取器 — 你不用直接调 Reflect.getMetadata,用 Reflector.get(handler, key) 即可,API 更干净

import { Reflector } from '@nestjs/core';
import { IS_PUBLIC_KEY } from '../common/decorators';

@Injectable()
export class ApiKeyGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (isPublic) return true;

    const request = context.switchToHttp().getRequest();
    // ... 原有逻辑
  }
}

3.4 · 新建 TimingInterceptor(全局)

新建 apps/gateway/src/interceptors/timing.interceptor.ts:

import { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable, tap } from 'rxjs';

@Injectable()
export class TimingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const start = performance.now();
    const req = context.switchToHttp().getRequest();
    return next.handle().pipe(
      tap(() => {
        const ms = (performance.now() - start).toFixed(2);
        console.log(`[Timing] ${req.method} ${req.url} ${ms}ms`);
      }),
    );
  }
}

几个细节:

  • performance.now() 是 W3C High Resolution Time API,Node 原生支持,精度亚毫秒
  • RxJS tap() 是"只观察,不修改"的 operator — handler 的返回值会原样传给 client,我们只是顺便记个时
  • 这个 Interceptor 不处理异常 — handler 抛错时,tap 不跑(异常走 Filter)。所以 0002 的 [AllExceptions] 日志会跟 [Timing] 互不干扰

3.5 · 在 AppModule 全局注册 TimingInterceptor

打开 apps/gateway/src/app.module.ts,改 providers 数组加一项:

import { APP_INTERCEPTOR } from '@nestjs/core';
import { TimingInterceptor } from './interceptors/timing.interceptor';

@Module({
  ...
  providers: [
    ProxyService,
    LifecycleProbeService,
    {
      provide: APP_INTERCEPTOR,
      useClass: TimingInterceptor,   // ← 全局注册
    },
    { provide: APP_GUARD, useClass: CasGuard },
    { provide: APP_GUARD, useClass: ApiKeyGuard },
    { provide: APP_FILTER, useClass: AllExceptionsFilter },
  ],
})

3.6 · LifecycleProbeService 加 OnModuleInit

打开 apps/gateway/src/lifecycle/lifecycle-probe.service.ts,加 import + 1 个方法:

import { Injectable, OnModuleInit, OnModuleDestroy, OnApplicationShutdown } from '@nestjs/common';

@Injectable()
export class LifecycleProbeService implements OnModuleInit, OnModuleDestroy, OnApplicationShutdown {
  onModuleInit() {
    console.log('[Lifecycle] OnModuleInit: module dependencies resolved');
  }

  onModuleDestroy() {
    console.log('[Lifecycle] OnModuleDestroy: closing connections (simulated)');
  }

  onApplicationShutdown(signal?: string) {
    console.log(`[Lifecycle] OnApplicationShutdown: signal=${signal}, flushing logs (simulated)`);
  }
}

现在 init/destroy 对称了 — 启动时一行 [Lifecycle] OnModuleInit,SIGTERM 时两行。
