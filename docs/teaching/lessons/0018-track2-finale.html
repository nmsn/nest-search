1. 跨服务追踪 — 一句话定义

用户请求 POST /api/auth/login 时,nest-search 内部实际经过:

  1. gateway(3000)— 接收请求 + JwtGuard + 转发
  2. auth-service(3004)— bcrypt 校验 + 生成 token + 写 Redis
  3. 可能 → MySQL / Redis / RabbitMQ

如果某一步报错,怎么定位"是哪个请求触发的"?

跨服务追踪:在请求进入的第一站(本例 gateway)给请求生成/读取一个 requestId,然后每经过一站都带上,该站 log 里都包含这个 id。事后 grep 一个 id,能拉出整个调用链。

2. 实操 · 跨服务追踪实测

2.1 · 准备 — 启 gateway + search-service

前提:MySQL + Redis + Elasticsearch + RabbitMQ 都在 docker-compose up 状态。

# 检查基础设施
lsof -i :3000 -i :3002 -P   # 端口空
docker ps --format "{{.Names}}: {{.Status}}" | grep -E "mysql|redis|elasticsearch"

# 临时打开 autoLogging(为了看到 HTTP 请求 log)
# 不改业务代码,只改 4 行 autoLogging: false → true
# gateway: apps/gateway/src/app.module.ts
# search-service: apps/search-service/src/app.module.ts
⚠️ autoLogging: true 会让每个 HTTP 请求打 1 条 log(prod 不推荐,太吵)。本节为了实测临时打开,实测完恢复 false。 
# 启服务
pnpm start:gateway > /tmp/gateway.log 2>&1 &
echo $! > /tmp/gateway.pid
pnpm start:search > /tmp/search.log 2>&1 &
echo $! > /tmp/search.pid
sleep 10

# 等"LoggerModule dependencies initialized" + "Mapped" 路由

2.2 · 实操 · 发带 trace 的请求

curl -H "x-request-id: trace-abc-002" \
     -H "x-api-key: ds_key_123" \
     "http://localhost:3000/api/search/ds/products?keyword=test"

期望响应:200 {"total":{"value":0,"relation":"eq"},"page":1,"size":20,"items":[]}。

2.3 · 实操 · grep 同一 trace

grep "trace-abc-002" /tmp/gateway.log
grep "trace-abc-002" /tmp/search.log

✓ gateway log 出现的两条(节选)

{"level":30, ... "req":{"id":"trace-abc-002", "method":"GET",
 "url":"/api/search/ds/products?keyword=test", ...
 "x-request-id":"trace-abc-002", ...},
 "requestId":"trace-abc-002",
 "context":"ProxyService",
 "msg":"Proxying GET /api/search/ds/products?keyword=test → search-service"}

{"level":30, ... "requestId":"trace-abc-002",
 "context":"TimingInterceptor", "method":"GET",
 "url":"/api/search/ds/products?keyword=test",
 "statusCode":200, "durationMs":26.18,
 "msg":"request completed"}

✓ search-service log 出现的一条(节选)

{"level":30, ... "req":{"id":"trace-abc-002", "method":"GET",
 "url":"/api/search/ds/products?keyword=test", ...
 "x-request-id":"trace-abc-002",
 "user-agent":"axios/1.16.0",   ← 来自 gateway 的 HttpClientService
 "host":"localhost:3002"},
 "requestId":"trace-abc-002",
 "res":{"statusCode":200}, "responseTime":15,
 "msg":"request completed"}

关键观察:

  • 两边都有 "requestId":"trace-abc-002" — 同一 trace
  • search-service log 里 user-agent: axios/1.16.0 — 证明请求来自 gateway 的 HttpClientService
  • gateway log 第一条 "context":"ProxyService" — 转发是 ProxyService 干的

2.4 · 清理 · 恢复 autoLogging + 杀进程

# 恢复 autoLogging: false(gateway / search 两个文件)
# 改完保存后:

kill $(cat /tmp/gateway.pid) 2>/dev/null
kill $(cat /tmp/search.pid) 2>/dev/null
lsof -ti :3000 -P | xargs kill -9 2>/dev/null
lsof -ti :3002 -P | xargs kill -9 2>/dev/null

# 验证:4 个服务都 autoLogging: false
grep "autoLogging" apps/{gateway,sync,form}-service/src/app.module.ts \
                    apps/search-service/src/app.module.ts

期望输出:全部 autoLogging: false。
