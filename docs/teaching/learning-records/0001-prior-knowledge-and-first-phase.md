# 0001 — 用户背景与第一阶段锚点

用户: 8 年高级前端开发工程师,会 React/TypeScript/打包工具/HTTP 协议,自述"基本没用过 Node",目标是 T 形工程师 / 能在本项目独立交付后端服务。学习方式是"边学边改 `nest-search`"。

为什么这条重要: 它直接决定了第一节课必须先补 Node 运行时,而不是直接进 NestJS 装饰器。如果跳过,后续 DI、异常过滤器、生命周期钩子的"为什么"用户都接不住,只能死记。

第一阶段锚点: **可观测性三件套** — 结构化日志 (Pino) + 请求链路 ID + 全局异常过滤器,加上顺带的健康检查和 Swagger。理由: 这套会强制他理解 NestJS 的"请求生命周期 + 异常流",是后续所有能力(鉴权、限流、测试、部署)的预演场。

**Implications for next sessions**:
- LR-NNNN 中不能跳过 Node 基础的"为什么"问题,即便看起来很初级
- 第一课需有"跑起来"的可见产物(`pnpm dev` 起 gateway,curl 看日志),避免抽象
- LR-0002 应该记下"项目里有什么、没有什么",作为后续补底任务的清单
